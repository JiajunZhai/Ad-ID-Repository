# Ad ID Warehouse

一个面向广告运营与变现配置的本地管理工具，用于按应用集中维护广告类型、广告位、流量分组和广告源 ID。项目采用原生 HTML、CSS、JavaScript 构建，并通过 Vite 开发服务器将每个应用保存为独立的本地 JSON 文件。部署为纯静态站点（如 GitHub Pages）时，数据自动降级为浏览器本地存储（localStorage），支持 JSON 备份导出/导入迁移。

## 功能概览

### 层级浏览

- 按“应用 -> 广告类型 -> 广告位 -> 流量分组”四级结构浏览配置
- 广告位下采用**单页手风琴**平铺全部流量分组，不再跳转到独立子页面
- 支持同时展开多个分组对照查看，或一键“全部展开 / 全部收起”
- 通过顶部**面包屑切换器**（`⌂ 应用列表 / 应用 ▾ / 广告位 ▾`）快捷切换层级，下拉支持就地搜索与键盘导航

### 流量分组（手风琴行）

- 每行折叠态展示：展开/收起指示、优先级阶梯徽标、分组名称、ID 状态健康胶囊、行内参考 eCPM 调价、快捷操作
- **ID 健康胶囊**三态：`● 9/9 就绪`（绿色）/ `◐ 3/9 待回填`（橙色）/ `○ 0 组待配置`（灰色）
- 优先级徽标按段位分色：P1~P3 橙紫、P4~P7 蓝、P8+ 灰

### ID 配置矩阵（展开面板）

- 展开分组后在行内嵌套类 Excel 网格：序号、广告源、组标识、计算底价、广告名称、广告 ID、Meta 来源 ID、联动、操作
- **批量生成** L/H/M 各 `n` 个 ID 槽位（共 3n 条，广告源固定为 Admob），并自动按组标识算好底价
- **整列复制**：一键复制全列广告名称或全列广告 ID（换行符分隔）
- **多行整列回填**：把一整列广告 ID/Meta ID 粘贴到任意输入框，按序覆盖当前分组前若干行，其余保留
- **草稿框拆行新增**：在“快速添加”草稿框粘贴多行，自动拆分为多条新记录
- H/M/L 组标识切换、🔒 锁定、删除 ID 槽位
- 广告 ID 为空时显示“待回填 ID”虚线占位；填入后转为实线绿底
- **Tab 纵向盲打**：焦点在广告 ID 输入框时，按 Tab 在同一分组内跨行跳转到下一行同列（Shift+Tab 反向）

### 自动化

- 根据流量分组 eCPM 与**组标识倍率**自动计算底价和广告名称
- 修改 eCPM 或 H/M/L 组标识后，锁定项自动重算底价与广告名称
- eCPM 与 ID 输入约 1 秒防抖自动保存
- 删除单个 ID 槽位、广告位（连带分组）或整个应用及其 JSON 文件

### 复制中心

- 全库 ID 扁平化平铺工作台：序号 / 应用·广告位 / 层级 / 标识 / 底价 / 广告名称 / 广告 ID / Meta ID / 业务状态
- **组合筛选**：应用（自定义下拉弹层，每项前显示缓存图标）、广告位、组标识 `L/M/H`、排序（标识/底价/瀑布流层级）、全局搜索
- **状态速筛 Tab**：全部 / 运行中 / 未创建 / 中介组未建 / Meta 未建，带实时计数；行内状态 Pill 点击切换四态
- **勾选与批量**：`Shift` 范围连选、`Ctrl+C` 直取选中广告 ID；批量浮条可一键打状态，或复制 ID / 名称 / 底价 / Meta ID / ID+底价(TSV) / 导出全列(TSV 贴 Excel)
- **格式模板**：自定义复制占位符模板（`{应用} {广告位} {层级} {标识} {底价} {广告名称} {广告ID} {Meta ID}`），实时预览

### Google Play 绑定与图标缓存

- 应用列表首列为图标四态：真实图标 / 未找到占位（代号前缀）/ 未绑定「＋」/ 加载中
- 绑定弹窗输入包名自动从 Google Play 抓取商店名称、开发者、分类与图标，一键写回
- 抓取结果缓存到 `data/play-meta.json` + `icons/` 本地文件（包名即文件名），避免重复请求；可强制刷新
- 行内可复制包名、绑定/改包名、刷新商店数据

### Excel 导入

- 从 XLSX 导入应用/广告位/流量分组/ID 配置，广告类型自动推断，未知类型与聚合平台复合值在预览中指定
- 底价与广告名称按公式重算，不采信表中偏差值；导入前预览差异化对账

### 快捷键

- `Ctrl+K`（macOS 为 `Command+K`）：聚焦搜索框
- `Alt+1`：返回应用列表
- 复制中心勾选后 `Ctrl+C`：直取选中行广告 ID
- `Tab`：广告 ID 输入框间纵向跳转
- `Enter`：提交当前草稿 / 确认下拉选择
- `Esc`：逐级关闭浮层、取消草稿（非输入时返回应用列表）

## 技术栈

- HTML5
- CSS3
- 原生 JavaScript（ES Modules）
- Vite（`package.json` 声明 `^5.0.0`，lockfile 收敛到 `5.4.21`，重装依赖请保持 5.4.x）
- Node.js 文件系统 API，用于本地 JSON 持久化
- `google-play-scraper`（仅开发服务器端调用，结果本地缓存）

项目没有引入前端框架、数据库或独立后端服务。持久化 API 由 `vite.config.js` 中的 Vite 中间件提供，仅用于本地开发环境。

## 快速开始

### 环境要求

- Node.js 18 或更高版本
- npm

### 安装依赖

```bash
npm install
```

### 启动项目

```bash
npm run dev
```

浏览器访问：<http://localhost:3333>

Windows 用户也可以双击 `AD ID.bat` 启动。Vite 配置会在服务启动后自动打开浏览器。

> 请优先通过 Vite 服务访问项目。直接打开 `index.html` 时本地 JSON API 不可用，应用会自动降级为浏览器本地存储（可用，但抓取/图标/Excel 导入不可用）。

### 构建静态资源

```bash
npm run build
```

构建结果输出到 `dist/`，可直接部署到任意静态托管（推荐 GitHub Pages）。需要注意，生产构建只包含静态前端资源，不包含 `vite.config.js` 中仅供开发服务器使用的本地存储 API —— 部署后的数据读写走浏览器 `localStorage`，首次需要「导出备份 / 导入备份」搬运数据（见「双模式持久化与静态部署」）。

### 预览构建结果

```bash
npm run preview
```

预览模式同样不会注册开发服务器的 `configureServer` 中间件，因此 `/api/apps` 会返回 404 —— 应用自动进入静态模式（浏览器本地存储）。适合预览界面，如需完整编辑数据请使用 `npm run dev`。

## 使用流程

1. 在应用列表中新建应用，填写应用名称、包名和支持平台。
2. 进入应用并创建广告类型，例如激励视频、插屏或横幅。
3. 在广告类型下创建广告位，并选择 TradPlus 或 Topon 等聚合平台。
4. 进入广告位，在单页手风琴中查看全部流量分组；点击某行或“全部展开”展开分组。
5. 在展开的 ID 矩阵中，使用“批量生成 L/H/M”预生成一组底价已算好的 ID 槽位，或逐条添加。
6. 将一整列广告 ID/Meta ID 粘贴到输入框进行整列回填；或在草稿框粘贴多行快速拆分新增。
7. 需要时切换 H/M/L 组标识、锁定、复制整列、删除槽位。

## 数据持久化

数据保存在项目根目录的 `data/` 文件夹中。每个应用对应一个 JSON 文件（文件名 = 应用名称）：

```text
data/
  PT001.json
```

文件名来自应用名称。新增、复制、删除和编辑配置时，前端会调用本地 API 更新对应文件。输入广告 ID 或修改 eCPM 时，会在约 1 秒后自动保存。`data/` 与 `icons/` 为运行期数据目录（已加入 `.gitignore`），开发服务器启动时自动重建。

### 双模式持久化与静态部署

应用启动时自动探测存储模式：

- **开发模式（默认）**：`/api/apps` 可用 → 数据写入 `data/*.json`（权威数据源），完整功能，含 Google Play 抓取与图标缓存。
- **静态模式**：`/api/apps` 返回 404 或不可达（GitHub Pages、`vite preview`、直接打开静态构建）→ 数据读写浏览器 `localStorage`（键 `adiw.warehouse`），侧边栏同步状态显示「静态模式 · 浏览器本地」。删除/新增/编辑全部可用；但 Google Play 抓取、图标缓存与 Excel 导入不可用（依赖 dev 中间件）。

**迁移（dev ⇄ 静态站）**：应用列表头部提供「⧓ 导出备份」与「⇪ 导入备份」。导出生成 `ad-id-warehouse-backup-<日期-时间>.json`；导入支持该备份文件（整体覆盖，需确认），也能接收 `{apps:[...]}` 结构。在 dev 上导出 → 在静态页导入即可搬运数据；反之亦然（静态模式数据单人单浏览器，请勿多人共用）。

> 静态模式数据仅存于当前浏览器，清理浏览器数据会丢失；建议静态站仅作为只读/轻编辑使用，权威数据始终留在 dev 的 `data/`。

## 本地 API

这些接口由 Vite 开发服务器中间件实现：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/apps` | 读取 `data/` 下的全部应用 JSON |
| `POST` | `/api/apps/save` | 新建或覆盖单个应用 JSON |
| `POST` | `/api/apps/delete` | 删除指定应用的 JSON 文件 |
| `GET` | `/api/play/lookup?pkg=` | 抓取 Google Play 应用信息（`?refresh=1` 跳过缓存） |
| `GET` | `/icons/*` | 本地图标缓存静态服务（长缓存） |

保存接口请求体：

```json
{
  "app": {},
  "oldName": null
}
```

删除接口请求体：

```json
{
  "name": "PT001"
}
```

## 当前限制

- 本地 API 没有鉴权，仅适合可信的本机开发环境。
- JSON 文件名直接依赖应用名称，应避免使用路径分隔符或操作系统不允许的文件名字符。
- 同名应用会写入同一个 JSON 文件，可能覆盖已有数据。
- 当前没有测试脚本、数据版本迁移或并发写入保护。
- 纯静态部署（GitHub Pages / `vite preview`）下数据保存在浏览器 `localStorage`：不能跨设备同步、清理浏览器数据即丢失，且 Google Play 抓取、图标缓存与 Excel 导入不可用；权威数据建议留在 dev 的 `data/`，通过 JSON 备份导出/导入迁移。
- 依赖版本已锁定：`package.json` 声明 Vite `^5.0.0`，锁定文件与已安装版本收敛到 `5.4.21`（与声明一致）；重装依赖请保持 5.4.x，勿混入 8.x。
- `data/`（含应用配置与 Play 元数据缓存）、`icons/`（图标缓存）为本地运行数据，已排除在版本库之外。

## 开发说明

界面使用集中式 `state` 保存当前导航位置，并通过 `render()` 重新生成各区域。点击和输入行为由文档级事件委托统一处理。修改数据后，`save()` 按 `MODE` 分流：开发模式调用 `/api/apps/save` 将当前应用完整写回 JSON 文件；静态模式写入浏览器 `localStorage`。

流量分组层为单页手风琴：`state.open` 记录当前展开的分组 ID 集合（可多开），维度卡片 / 顶部按钮负责“全部展开 / 全部收起”。每个分组的 ID 矩阵由 `segmentPanel()` 内嵌渲染，`draft.seg` 记录草稿所属分组，避免多开时串组。

广告名称的默认生成规则为：

```text
应用名_广告源_广告位代码_流量分组_组标识_底价
```

底价按组标识倍率计算：

```text
L 组底价 = eCPM × 1.15
H 组底价 = eCPM × 1.35
M 组底价 = eCPM × 1.80
```

当 ID 配置处于锁定状态时，修改流量分组 eCPM 或 H/M/L 组标识会重新计算 `floorPrice` 和 `adName`。
