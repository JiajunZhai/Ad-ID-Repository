# Ad ID Warehouse UI/UX 重设计执行计划
基于用户提供的详细设计方案制定的渐进式实施计划。
## 一、设计方向分析与现状对比
### 现状
- 使用现有 CSS 变量系统，支持亮暗主题
- 应用列表采用表格布局
- 顶部：面包屑 + 状态胶囊 + 搜索框
- 操作按钮：hover 显示
- ID 状态：pill-ok/partial/empty（三态）

### 核心目标
1. 顶部工具栏拆分为两层（全局导航 + 页面操作栏）
2. 页面操作栏增加统计卡片
3. 搜索扩展支持应用名、包名、开发者等字段
4. 优化应用列表信息层级与行高
5. 改进 ID 状态表达与异常提示
6. 移动端与桌面端分别优化

## 三、实施顺序
### 阶段 1：视觉统一（设计 Token 与基础样式）
- [ ] 扩展或调整 CSS 变量以匹配新的色板
- [ ] 统一按钮高度、圆角、间距、字体层级
- [ ] 优化表格行高、分隔线、悬停背景

### 阶段 2：操作优化
- [ ] 统一 Tooltip、悬停操作、复制反馈
- [ ] 改善危险操作区分和二次确认逻辑
- [ ] 增强键盘可访问性

### 阶段 3：信息识别
- [ ] 扩展应用列表搜索字段
- [ ] 优化 ID 配置状态展示
- [ ] 增加筛选与排序能力

### 阶段 4：效率优化
- [ ] 响应式细节优化
- [ ] 性能与可访问性改进

## 四、最小可实施改动（现状可直接优化）
1. **搜索扩展**（已部分完成）- appsViewV2 已支持多字段搜索
2. **样式微调** - 行高、应用信息层级、移动端适配
3. **搜索提示文案** - 根据视图动态调整

## 五、风险评估
- 保持现有功能不变，优先样式与渲染层调整
- 避免修改业务逻辑（数据模型、持久化、导入导出）
- 渐进式改动，单个提交范围小

## 六、验证要点
- npm run build 构建成功
- 开发模式与静态模式正常
- 移动端布局不破坏表格可读性
- 图标加载与降级正常
